1The verdict

The core is genuinely strong; the edges are rougher than the compliance doc admits.

The heart of a compact-model compiler — contributions, probes, automatic differentiation, the DAE the simulator solves — checks out quantitatively everywhere it was measured: $mfactor scaling follows all four normative rules to machine precision, noise densities match hand-computed physics, laplace/zi filters match closed-form responses, and parameter override order, dependence, and range enforcement behave per the letter of clause 3 and 6. That is the hard part, and it is right.

The confirmed bugs cluster at the simulation-lifecycle boundary — where language semantics meet the Newton loop. Display and file I/O run on every solver iteration instead of accepted steps (LRM 9.4.6/9.5.9); the analysis()/event machinery misreports which phase is running (Table 4-22, Table 5-1); cross()/above() ignore their normative timing rules; and several silent no-ops in hierarchy elaboration (defparam next to generate, .$mfactor() child overrides, $param_given on flattened children) produce wrong numbers with no diagnostic — the most dangerous class in this report.

The single most consequential group: silent wrong answers. A model that compiles clean and runs is trusted. Eleven confirmed findings produce numerically wrong results or dead code with zero warnings — they are marked silent below and are the recommended first fixes.

2How the audit ran

Fifteen areas were audited against assigned page ranges of the LRM (chapters 2–6, 9, 10 and annexes B/C/D/E — the Verilog-A analog subset per Annex C; digital/mixed-signal clauses were checked only for clean rejection). For each area: the normative text was read first, then the implementation (lexer → preprocessor → parser → hir_def/hir_ty → hir_lower → mir/sim_back → osdi, plus ngspice-46/src/osdi/*.c), then behavioral micro-tests were compiled with the committed openvaf-r and simulated with the committed ngspice. Roughly 140 test decks were written and 530+ Verilog-A files compiled.

Every non-note finding was then adversarially re-verified: the cited LRM pages were re-read from the PDF (never from memory), the cited code re-read, and the behavior re-reproduced; claims of outright bugs got two independent verification passes (LRM-interpretation lens and code-behavior lens). One candidate finding failed re-verification and was withdrawn (§7). The repo's own compliance document, docs/compliance/OpenVAF_Verilog-A_LRM_Compliance.md, was treated as an audit target, not a source of truth.

Silent wrong results — hierarchy & elaboration

bug · silentdefparam silently dropped in any module containing a generate constructLRM 6.3.1 p.138
A module-scope defparam works in plain modules (verified to two levels, winning over instance overrides) — but the moment the same module contains any generate construct, every defparam (module-scope or inside generate blocks) is dropped by the generate-rewriting pass with no diagnostic.
defparam u1.g=7e-3 + unrelated generate: expected 8 mA → observed 2 mA (default applied)

Hierarchical system parameters may be overridden "using … module instance parameter value assignment by name". The paramset path works (.$mfactor = 4; inside a paramset scales correctly), and defparam u1.$mfactor at least errors — but the instance-override spelling is silently ignored.
child #(.$mfactor(4)): expected −4 mA → observed −1 mA; #(.$xposition(0.005)): expected −6 mA → −1 mA
bug · silent$param_given() is always false for parameters overridden inside the VA hierarchyLRM 6.3.5 / 9.19 p.141
Compile-time flattening bakes a child-instance override in as the parameter's new default, so $param_given reports "not given". Netlist-level (.model) overrides report correctly.

bug · silentScalar net connected to a vector port is accepted and wired to every bitLRM 6.5.7.1 p.152
"The sizes of the ports and net need to match." A scalar actual on a 2-bit port compiles, elaborates, and simulates with the scalar replicated onto both bits.
twobit u2 (p, o) with p scalar: ran; both v2[0] and v2[1] read V(p) → v(out2) = −3 V
bug · silentMixed ordered + named parameter overrides accepted; the positional part is droppedLRM 6.3.2/6.3.3 (Syntax 6-2) p.136
The grammar makes the list all-ordered or all-named. #(5e-3, .g2(7e-3)) compiles without diagnostic and applies only the named half. (The equivalent mixing for ports is correctly rejected with a model error message.)
#(5e-3, .g2(7e-3)): expected −12 mA (or an error) → observed −8 mA (g1 kept its default)
bugHierarchical contribution merges into the child's unnamed branch instead of creating a new oneLRM 5.6.8.1 p.116
"A new unnamed branch is created in the module containing the direct contribution statements." The parent's V(p, c1.mid) <+ 0.5 instead merges with the child's own source branch, corrupting the child's flow mirror.

Silent wrong results — events & analysis state

bug · silentUnrecognized event expressions silently degrade to "run always"LRM 5.10 / Annex C.7 p.122, 390
Any @(…) whose expression isn't a recognized event — absdelta (digital-only, must be rejected), a named event, or a simple typo like cros — drops the event control entirely and runs the guarded statement on every evaluation.
@(absdelta(V(p,n),0.1)) na=na+1: expected never (rejection) → na=120 in a 10-point transient
bugcross() fires during DC sweeps and at t=0LRM 5.10.3.2 p.128
"cross() can only generate an event after the simulation time has advanced from zero" and "will not generate events for non-transient analyses, such as ac, dc, or noise". Pure sign-change detection fires it in .dc and during the t=0 operating-point Newton walk.
bugabove() misses its mandatory initialization eventLRM 5.10.3.2 p.128
"If the expression is positive at the conclusion of the initial condition analysis … above() shall generate an event." The previous-value state is seeded with the current value at initial-step, so an always-positive expression never fires.
@(above(V+0.5)), V=1.0, .tran: expected 1 event → observed 0
buginitial_step/final_step analysis lists fire for the wrong analysesLRM 5.10.2 Table 5-1 p.124
During .ac, both initial_step("ac") and initial_step("dc") fire (Table 5-1: dc = 0 in every AC column); during .noise, initial_step("dc") and final_step("ac") fire alongside the correct noise events. Cause: the OP phase carries both DC and parent-analysis flags (ngspice osdiload.c).
bugEvent placement restrictions unenforced: nested @, cross under non-genvar if/while, filters in event expressionsLRM 5.10/5.10.3.1 p.123, 128
All three normative prohibitions compile silently. Nested @(initial_step) @(final_step) lowers to an AND-gate that can never fire — a silently dead statement. (The body-side check exists: ddt in an event body is caught.)
buganalysis("ic")/analysis("static") window displaced from the transient OP to the first timestepLRM 4.6.1 Table 4-22 p.87
At the t=0 transient operating point both must return 1 (and 0 at timesteps). Observed: 0 at t=0, then 1 on the first evaluation at the first timestep — exactly one phase late.
t=0: ic=0 static=0 | first step t=3e-10: ic=1 static=1 (LRM: the reverse)
bug · silentac_stim() is active during .noise, poisoning input-referred noiseLRM 4.6.3 p.88
ac_stim must return 0 "on all small-signal analyses using names which do not match analysis_name". ngspice's noise analysis reuses the AC loader, which activates every stim matching the literal "ac".
inoise with an ac_stim module present: 5.752e-12 vs 5.758e-9 control — 1000× wrong, no warning

Natures, disciplines, expressions

bugDiscipline compatibility rejects LRM-compatible signal-flow and natureless connectionsLRM 3.11.1 p.46
The Non-Existent Binding Rule and Natureless Discipline Rule make electrical↔voltage (sig_flow_v) and natureless-continuous connections compatible — the LRM works this exact example. DisciplineTy::compatible returns false whenever one side lacks a nature the other has (_ => return false).
bugNature attribute validation is dead code; illegal forms accepted and silently droppedLRM 3.6.1.2 p.36
The intended checks iterate nature.attrs() — the (* *) annotation accessor — instead of the actual nature items, so they never run. access = "SA" (a string, illegal) compiles clean and the access function silently doesn't exist.
bugOSDI natures table: num_attr off by one for every natureOSDI 0.4 export of LRM 3.6.1.2
let i2 = attr_vec.len() + 1; inflates every nature's attribute count; consumers walk into the next nature's attributes (or out of bounds for the last). Latent in ngspice (which doesn't read the table), live for any other OSDI consumer.
bugSame-node signal access V(a,a)/I(a,a) accepted; Table 4-16 marks it ErrorLRM 4.4 Table 4-16 p.64
Compiles and yields constant 0 / branch short instead of the mandated error.
bug · silentModulus by deck-supplied zero is silent NaNLRM 4.2.4 p.55
"It shall be an error to pass zero (0) as the second argument to the modulus operator." A compile-time literal zero is caught; a model-card-supplied zero propagates NaN with no report.
bugtransition() with explicit zero rise/fall ignores `default_transitionLRM 4.5.8 p.73
"If neither rise_time nor fall_time are specified or are equal to zero, the rise and fall time default to the value" of the directive. Explicit zeros bypass the directive path.
bugBlock-level variables with desc/units become output variables, colliding across blocksLRM 3.2.1 p.25
Output variables are module-scope declarations with descriptions. Two named blocks each declaring (*desc*) real t both export as instance parameter t; ngspice warns it "cannot tell the names apart".

6Compliance-doc mismatches 9 confirmed

Places where docs/compliance/OpenVAF_Verilog-A_LRM_Compliance.md claims more than the binaries deliver. The doc is honest about several deviations (limexp, zi_*, range-exemption, generate-on-parameters) — these are the claims that are not.

doc§7.1 Display "✅ … verified against exact printf output" including %r
%r prints garbage for every value; $monitor has no monitor semantics; all display fires per Newton iteration. None disclosed.
doc§6 Hierarchy "✅" — "defparam with its LRM precedence", "generate in all three forms"
The doc's own §6 example pairs defparam with generate — the combination in which defparam is silently dropped. Multi-construct regions, descending loops, and generate-block hierarchical refs all fail; none of the five silent hierarchy bugs are disclosed.
doc§5.5 Events "✅ — cross/above/timer with tolerances"; "analysis-phase lists filtering by analysis type"
cross/above tolerances are parsed and ignored (5,600× the requested tolerance measured); phase lists fire for wrong analyses.
doc"Verilog-A has no break/continue, and the compiler says so with the disable idiom in the diagnostic"
VAMS-2023 §5.11 defines jump statements and Table B.1 reserves the words; the compiler emits no such diagnostic — break compiles as an ordinary identifier.
docThree §4.5 operator claims contradicted by measurement
"`default_transition` defaults" (explicit-zero case broken), transitions "reach their final value at delay + trise" (amplitude-scaled), Table 4-20 constant/dynamic split "honoured exactly" (dynamic coefficients track).
doc$table_model presented with an example that cannot compile
The showcased 2-D "mos_iv.tbl","1L" call fails against LRM-format files; clause cited as 9.19 (it is 9.21).
docac_stim example implies degrees
ac_stim("ac", 1.0, 90.0) — phase is radians (implementation verified correct: 1.5708 → exactly +90°); 90.0 rad only makes sense as a degrees mistake.
docAnalog functions marked a blanket pass
Two compiler crashes (string type, local parameter), the failing LRM array example, zero-init of output args, and the missing 2023 return statement all sit under a ✅.
docparamset cited as "Verilog-AMS 3.4.6"
LRM 3.4.6 is String parameters; paramsets are clause 6.4.

8What is solidly conformant

219 load-bearing requirements verified positively — by measurement, not by reading the docs. The highlights:

  • $mfactor core semantics (6.3.6) — flow contributions ×m (−4 mA at m=4), potentials unscaled, flow probes ÷m (0.5 mA), noise power ×m (onoise matched √(4·S·R²+4kTR) to 6 digits), $mfactor readable in-module, ngspice m= and paramset .$mfactor both correct.
  • Analog operators numerically — ddt AC = jωC; absdelay DC pass-through and e^{−jωτ} phase; idt with ic; ddx(V·V, V(a)) = 2V; laplace_* match closed-form H(s) to ~5e-16; zi_* match bilinear H(z⁻¹) to 1e-15; last_crossing interpolation; slew band behavior incl. the LRM's negative max_neg_rate.
  • Noise quantitatively (4.6.4) — white_noise 4kT/R against an ideal resistor's Johnson noise; flicker 1/f^exp slopes; noise_table interpolation; distinct-label sources RSS-combine as uncorrelated.
  • Parameter machinery (3.4, 6.3) — from/exclude ranges enforced at runtime with located netlist errors; localparam non-overridable; ordered override skips localparams and aliases; excess positional and duplicate named overrides are errors; dependent defaults recompute through both VA and netlist overrides; $param_given/$port_connected correct at the netlist level.
  • Contribution semantics (5.6) — accumulation of multiple <+, switch-branch V/I selection with value retention, indirect contributions (ideal-opamp idiom solves), port-flow access I(<p>), unassigned-source defaults.
