1The verdict

The numerical core is excellent. What still breaks is state that spans calls — file position, RNG seed, instance identity.

Everything that can be checked against a closed-form answer was checked, and it is right: the three laplace forms land on −3.01030 dB and −45.000° at the pole frequency; ddt, idt, ddx and absdelay match analytic values exactly on a ramp; ln1p(1e-16) returns 1e-16 where a naive ln(1+x) collapses to zero, which is the entire reason that function exists; all fifteen parameter-range boundary cases resolve with the correct open/closed sense, including exclude (30:40]. That is the hard part of a compact-model toolchain and it is in good order.

The six findings share a shape. Each one involves state that has to survive from one call to the next — a file's read position, a random seed, an instance's identity, a nature's tolerance — and in each case that state is either dropped at a boundary or was never given a channel to travel through. None of them is a mistake in a formula.

Three findings produce wrong numbers or wrong data with no diagnostic on any channel: the RNG seed that never advances (a sampling loop silently returns one value N times), $fclose+$fopen that does not rewind (a re-read file yields different data), and the multichannel descriptor that is not a bit mask (the LRM's multi-file write lands in an unrelated file). Those are the recommended first fixes.

2How this pass ran

For each of the fifteen assigned areas the normative LRM text was extracted from the PDF and read first — never quoted from memory — then micro-models were written, compiled with the committed openvaf-r, and simulated with the committed ngspice. Expected values were derived independently (closed-form algebra, or Python/scipy for the numerical ones) so that a disagreement means something.

Every finding was then pushed until it named a cause: the offending line in openvaf/hir_lower, openvaf/osdi/stdlib.c or ngspice-46/src/osdi. Two candidate findings were withdrawn after re-reading the LRM (§5). This pass deliberately did not re-test the 39 bugs the August audit fixed; it re-read the same clauses looking for what the earlier sweep had not exercised.

3The six findings

Silent wrong answers

bug · silentThe random-number seed is never advanced, so a sampling loop returns the same draw every iterationLRM 9.13.1 p.238
The LRM is unusually explicit: the seed “is an inout argument; that is, a value is passed to the function and a different value is returned … only updated by the system function”, and the function “returns a new 32-bit random number each time it is called”. Measured: s=1234 before $random(s), and after three successive calls s is still 1234 — the variable is never written back. Consequently one call site executed repeatedly cannot advance, and the canonical Monte-Carlo idiom degenerates to a constant with zero variance and no warning. Distinct call sites do get independent streams, which is why per-instance mismatch modelling works and why this went unnoticed.
one call site, 5 loop iterations → 0.3361617 five times (1 distinct value, not 5)
20000 iterations of $rdist_uniform(s,2,8) → min = max = mean = 6.824131
$rdist_normal(s,5,2) over 20000 → mean 3.547, sd NaN (variance is exactly zero, rounded negative)
$rdist_exponential(s,3) → 2.12
bug · silent$fclose followed by $fopen does not rewind — a re-read file yields different dataLRM 9.5.1 / IEEE 1364
Opening a file for reading must start at byte 0. Measured on a three-line file: open, $fgets → line 1 (correct); $fclose; open again, $fgets → line 2. The stream position survives the close.
Cause. osdi_fopen (openvaf/osdi/stdlib.c:631) dedups by filename and returns the existing descriptor, re-opening only when !osdi_io_managed && osdi_file_close_req[i]. Once the I/O deferral machinery is engaged the freopen branch is skipped and the old position is kept. The dedup comment reasons only about the per-evaluation open-write-close idiom; the cost falls on the read path, which appears unintended.
a model re-reading a lookup table per instance or per temperature point silently gets different rows each time, then EOF
bug · silentMultichannel descriptors are sequential integers, not bit masks — the LRM's multi-file write lands in an unrelated fileLRM 9.5.1 p.228
The LRM defines a multichannel descriptor as “a 32-bit integer in which a single bit is set”, reserves “the least significant bit (bit 0) … always refers to the standard output”, and specifies that output goes to several files “by bitwise OR-ing together their multichannel descriptors”. Measured: $fopen("fa")→1, $fopen("fb")→2, $fopen("fc","w")→3 — consecutive integers drawn from one namespace shared with file descriptors.
$fdisplay(mA|mB, "both") wrote to neither file: 1|2 = 3 aliased the third file's descriptor, so the text landed in fc.txt
the first user file is handed descriptor 1, the value the LRM reserves for stdout; $fdisplay(1, …) before any $fopen produced no output at all

Other bugs

bug%m prints the module name, so it cannot identify the instance it exists to identifyLRM 9.4.4 p.229
“%m … causes the display task to print the hierarchical name of the module … which invokes the system task. This is useful when there are many instances of the module … the %m format specifier pinpoints the module instance responsible.” One module instantiated four ways prints the same string every time.
Cause. hir_lower/src/fmt.rs:85 expands %m to self.path, and lib.rs:578 sets let path = self.module.name(self.db) — the module name, baked into the format literal at compile time, so no instance information can reach it. The correct name is demonstrably available at run time: ngspice's own prefix on the very same lines reads OSDI na: and OSDI n.x1.nsub:.
instances na, nb, x1.nsub, x2.nsub → all four print m=fmt
bug$fscanf consumes the whole line, so a following $fgets silently loses the remainderIEEE 1364 (via LRM 9.5)
$fscanf should consume only what its format matches, leaving the rest of the line for a following $fgets — the ordinary “scan the numbers, take the trailing label” idiom. Measured within a single open (so unrelated to the reopen finding above): $fscanf(fd,"%d %g",iv,rv) correctly returns iv=10 rv=1.5 and a match count of 2, but the following $fgets returns "20 2.5 beta" instead of the remainder " alpha". A pure $fgets sequence is correct, which isolates the defect to $fscanf.
Cause. hir_lower/src/expr.rs:2469 lowers $fscanf as “Read one line from the descriptor, then scan it like $sscanf” — a Fgets call feeding a whitespace tokenizer (osdi_scanf_begin, stdlib.c:1010). Consuming a whole line is therefore structural, not incidental.

ABI gap

gap · silentA nature's abstol is parsed and then discarded; it never reaches the simulatorLRM 3.6.1 p.34
abstol is a required nature attribute whose purpose is the absolute convergence tolerance the simulator applies to signals of that nature — the standard natures set Current 1e-12, Charge 1e-14, Voltage 1e-6, Flux 1e-9, Temperature 1e-4. Every occurrence of abstol in the whole openvaf-r tree is inside the built-in disciplines.vams text (vfs/src/va_std.rs); nothing lowers or emits it. The OSDI ABI has no field for it either: OsdiNode (osdi.h:158) carries name, units, residual units, offsets, a nodeset and is_flow, but no tolerance. ngspice's only abstol is the global one from .options.
So a declared abstol has no effect: every node is converged against ngspice's global tolerance chosen by node kind. Nothing reports that the declaration was dropped. This is an ABI-level gap rather than a coding slip — closing it needs a tolerance field on OsdiNode plus ngspice honouring it at node registration.

4What was measured and holds

Positive results, each from a run against the committed binaries with an independently derived expectation.

Lexical conventions & directives (LRM 2, 10)

Underscores ignored in numbers (27_195_000, 236.123_763_e-12); every Table 2-1 scale factor exact, with M = 1e6 per the LRM rather than SPICE's milli; all six invalid real forms the LRM lists (.12, 9., 4.E3, .2e-7, .1p, 34.M) rejected. String escapes byte-exact including octal \101→A, \60→0, \7→BEL. Escaped identifiers work and an escaped keyword (\analog) is correctly not a keyword. Block comments do not nest. Every clause-10 directive is accepted; `begin_keywords "1364-2005" is honoured with a located warning that it maps to VAMS-2023. Macros with arguments, `__FILE__ and `__LINE__ all exact.

Data types & parameters (LRM 3)

All fifteen range-boundary probes resolve correctly, including the subtle exclude (30:40] where 30 is legal and 40 is refused. The LRM's rule that a default may sit outside its own range while only the instance value is an error is respected — openvaf-r warns (lint L027, with a documented suppression attribute) and compiles. String parameter value lists (from '{"NMOS","PMOS"}) accept and refuse correctly. Real→integer rounds away from zero (2.5→3, −2.5→−3). localparam cannot be set from the netlist and ngspice says so.

Expressions & math (LRM 4)

Both function styles agree ($ln(x) = ln(x)); traditional log() is correctly the decimal log. ln1p(1e-16)=1e-16 and expm1(1e-16)=1e-16 where the naive forms give 0 — the accuracy guarantee genuinely holds. hypot, atan2, pow, log10 exact; min/max/abs preserve integer type and promote correctly on mixed operands.

Natures, disciplines, branches (LRM 3.6–3.10)

User-defined natures, derived natures (nature x : parent), user disciplines (conservative and signal-flow), named branches and user-defined access functions all work end-to-end with exact values. (The abstol gap is §3.)

User-defined functions, events, analog operators, filters (LRM 4.5–4.7, 5.10)

Analog functions: input/output/inout formals, accumulation through an inout, return via the function name, integer return type — all exact. The LRM's restrictions are enforced: access functions, ddt/idt and recursion are all rejected inside an analog function.
Events on a five-cycle triangle: cross(+1)=5, cross(−1)=5, cross(0)=10, timer(0,1u)=6, above()=5, one initial_step, one final_step.
Core operators against analytic values on a 1 V/µs ramp: ddt=1e6, idt=1.8e−5, ddx(V²,V)=2V=12, absdelay(1µs)=V(5µs)=5.
laplace_nd / laplace_zp / laplace_np → −3.01030 dB and −45.000° at fc (analytic: 20·log₁₀(1/√2), −45°)
the LRM's null-argument form for “no zeros” (two adjacent commas) is supported; {} is correctly refused
transition(td=1u,tr=2u) half-way at 3.006 µs; slew(+1e6,−5e5) crosses 0.5 V at 1.499 µs rising and 12.0 µs falling

Hierarchy, analog behaviour, analysis & noise (LRM 5, 6)

By-order and by-name parameter overrides and port connections all take effect (a four-deep series chain lands on exactly −1.000 mA). Multiple analog blocks are allowed and concatenate in order (((1·10+2)·10+3)=123). Contributions accumulate; indirect assignment V(a,b) : I(a,b) == 1e-3 forces exactly 1 mA; switch branches toggle potential/flow. analysis() reports correctly in every mode, and a noise function evaluates to 0 in large-signal analyses per LRM 4.6.4.

Kernel functions and the OSDI layer

$temperature=300.15 K; $vt=0.02586493 and $vt(300)=0.0258520, both matching kT/q exactly. $param_given distinguishes set from defaulted; $simparam returns its default for an unknown name. $mfactor scales currents exactly (m=1,2,4 → 1,2,4 mA). $bound_step is honoured (a 1 ns bound over 1 µs gives 1005 points against 59 unbounded). $limit's unknown-function fallback warns per LRM 9.17.3.

The Annex C/E boundary

The sharpest test in this area passes: 1M in Verilog-A source is 1e6 per LRM Table 2-1, while 1M on a SPICE .model card is 1e−3 and 1MEG is 1e6 per SPICE rules. The same token correctly means different things on either side of the boundary. Annex C's exclusions hold: reg, wire, always, digital initial, task and continuous assign are all rejected.

5Things that looked wrong and are not

Recorded so the next audit does not re-litigate them.

An empty zero list {} for laplace_zp is refused
This looked like a gap until the clause was read: LRM 4.5.11 specifies the “no zeros” spelling as a null argument — “characterised by two adjacent commas” — not an empty concatenation. laplace_zp(V(in), , {…}) compiles and gives the exact analytic response, and refusing {} as an empty concatenation is correct.
Multiple analog blocks in one module are accepted
Not a subset violation: LRM 6.2 explicitly permits them and requires that they “are concatenated in the order they appear”, which was then verified with an order-dependent chain.
white_noise() and $temperature inside an analog function
Accepted where a strict reading of LRM 4.7.1 might exclude them, but both behave correctly — noise written through a function gives byte-identical output to the inline form (2.878521e−09 either way). Recorded as a permissive extension, not a defect.
%* assignment suppression in $fscanf
Not implemented — but refused at compile time with an explanation of exactly what would otherwise go wrong (“the field would be stored into the next destination instead of discarded”). This is the model the other findings should follow: missing, and loudly so.
