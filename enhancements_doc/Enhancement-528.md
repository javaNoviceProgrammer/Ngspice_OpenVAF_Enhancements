# Enhancement-528: analysis phases and noise, audited against the LRM

**Scope:** Accellera VAMS-2023 clause 4.6, from the full LRM conformance
audit — the transient operating point's misplaced `ic`/`static` window, the
never-set `nodeset` flag, `ac_stim` poisoning `.noise`, and noise
correlation keyed on the label instead of the call.

**Suite:** [`examples/lrmnoise_examples/`](../examples/lrmnoise_examples/)
— 17 checks, both solvers, plus the rewritten
[`noisecorr`](../examples/noisecorr_examples/) suite (LRM call-site
semantics) and an updated `noisejw` fixture. The full 440-suite sweep is
ALL OK. (Two further audit findings here — `analysis("dc")` at the AC/noise
op and the post-noise `final_step` ac flag — were already fixed by E-522
and re-verified.)

## The tran OP's ic/static window was displaced (ngspice)

LRM Table 4-22's TRAN OP column: `analysis("ic")` and `analysis("static")`
shall be 1 at the operating point that precedes a transient — that is what
makes 4.6.1's own idiom, `if (analysis("ic")) V(cap) <+ v0; else I(cap) <+
ddt(C*V(cap));`, apply its initial condition at the op. The bits rode
`MODEINITTRAN`, which ngspice raises at the FIRST ACCEPTED TIMESTEP
(t > 0): 0 exactly where the LRM requires 1, and the IC forced
mid-transient. They now map to `MODETRANOP`; the probe shows `ic=1
static=1 tran=1 dc=0` at exactly the one t = 0 evaluation and zeros at
every timepoint.

## analysis("nodeset") had no writer (ngspice)

4.6.2: true "during the phase of an operating point calculation in which
nodeset values are applied". The `ANALYSIS_NODESET` flag existed in the
shared header, the compiler tested it, and no ngspice code path ever set
it. It is raised exactly while ngspice enforces `.nodeset` values —
`MODEINITJCT`/`MODEINITFIX` with `CKThadNodeset` — verified with a latch
model: 1 with a `.nodeset` card, 0 without.

## ac_stim matched the literal "ac" (ngspice)

4.6.3: ac_stim "returns zero on all small-signal analyses using names
which do not match analysis_name". ngspice's `.noise` reuses the AC loader
for its gain solve, and the activation compared against the literal
`"ac"` — so an `ac_stim("ac")` source was injected into the noise gain
solve (measured: input-referred noise 5.75e-12 against a 5.76e-9 control,
exactly the poisoning the injected stimulus predicts), while
`ac_stim("noise")` could never activate even though this simulator itself
names the analysis "noise". The match is now against the RUNNING
small-signal analysis (`MODEACNOISE` → "noise"); the two decks swap roles
exactly.

## Correlation follows the call, the label reports (compiler + ngspice)

4.6.4.6: "Each noise function generates noise which is uncorrelated with
the noise generated by other functions. Perfectly correlated noise is
generated by using the output of ONE noise function for more than one
noise source" — and 4.6.4.1 makes the name a REPORTING label whose
contributions are "combined in the noise contribution summary". E-42's
coherent-amplitude machinery was keyed on the name string, which made two
separate same-labelled calls one physical source: `V(a,b) <+ wn(p,"w");
V(b,c) <+ -wn(p,"w");` cancelled to 0 where the LRM requires the
uncorrelated √2 power sum.

The correlation key is now the CALL SITE: hir_lower's per-call index
(which already existed to keep calls distinct through optimization)
threads through the topology extraction and the DAE into the OSDI source
name after a `\x1f` separator. ngspice correlates on the full string — so
every entry extracted from one call (the shared-output idiom, anti-phase
cancellation, scaled uses, `ddt()`-shaped waves) keeps summing coherently
— strips the suffix for the per-label summary vectors, and folds a
label's powers onto one report entry. Verified on every axis: the
variable-routed pair cancels to an exact 0, the same-label pair reads
√2·1e-6, distinct labels unchanged, cross-kind and cross-instance stay
independent, and a (1e-18 + 3e-18) same-label pair reports as one 4e-18
summary vector. One OSDI snapshot and five topology/dae dumps updated —
every diff is exactly the new `idx` field and name suffixes.

## Documented

`noise_table`'s array-parameter vector and string-parameter filename forms
(4.6.4.3) are disclosed as located refusals — the table bakes at compile
time and a deck-overridable parameter cannot feed it by construction. The
compliance doc's `ac_stim` example phase changed from the misleading
`90.0` to `` `M_PI/2 `` (the LRM defines phase in radians, which the
implementation honors exactly), and the noise-correlation paragraph no
longer overstates the old name-keyed behavior as LRM-conformant.
