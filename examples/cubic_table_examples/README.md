# cubic_table_examples — natural cubic-spline `$table_model` (Enhancement-22)

Demonstrates **natural cubic-spline** interpolation in `$table_model` (control
code `"3"`), using **version11's own** `openvaf-r` and `ngspice-46`. This extends
the piecewise-**linear** (Enhancement-16, 1-D) and **multilinear** (Enhancement-17,
2-D/3-D) interpolation with a **C¹** interpolant — its derivative is *continuous*,
so a table-based device's `gm`/`gds` are smooth instead of a staircase.

## Selecting the interpolation

The interpolation degree is chosen by the `$table_model` **control string**: a
`3` anywhere selects natural cubic spline, otherwise the interpolation stays
multilinear (as before). Extrapolation is still `L` = linear / else clamp. For
example:

```verilog
I(p,n) <+ $table_model(V(p,n), '{0.0,0.0, 0.5,0.48, 1.0,0.84, ...}, "3");   // cubic
I(a,b) <+ $table_model(V(a), V(b), "surf.grid", "3,3");                     // 2-D cubic
```

## How it stays differentiable

A natural cubic spline's per-point second derivatives (the "moments") are the
solution of a tridiagonal system that is **linear in the grid values and depends
only on the grid**. So the moment vector is a *compile-time-fixed linear
operator* on the values, and each moment is just a constant-weighted sum of the
(possibly runtime) grid values. The whole spline therefore lowers to plain
differentiable MIR — no runtime linear solve — and `mir_autodiff` supplies the
exact, continuous Jacobian for free (the AC `gm` below *is* that Jacobian). For
N-D, the same recursive-1-D scheme as Enhancement-17 yields the exact
tensor-product natural spline.

## Run

```
python3 verify_cubic_table.py
```

Expected (`ALL PASS`) — each check contrasts cubic with linear:

- **accuracy** — cubic tracks `sin(V)` ~40–50× better than linear at off-grid points;
- **smoothness** — across a grid node the cubic `gm` matches `|cos(V)|` on both
  sides (continuous), while the linear `gm` **jumps** ~10× more;
- **exactness** — a natural cubic spline reproduces straight-line data exactly;
- **N-D** — 2-D tensor-product cubic reproduces `sin(x)·cos(y)` accurately.

`surf.grid` is (re)generated by the script.

## Notes / limitations

- Natural boundary conditions (zero second derivative at the ends); extrapolation
  clamps to the endpoint value, or continues the spline's end tangent with `L`.
- A `3` in the control string applies cubic to **all** axes (matching E-16/E-17's
  global-control simplification); per-axis interpolation degree is future work.
- Requires at least 3 grid points along an axis; with fewer it falls back to
  linear.
