# rng_examples — Enhancement-10 random / statistical system functions

End-to-end verification of the Verilog-AMS random-number and
statistical-distribution system functions implemented in Enhancement-10, using
**version11's own** `openvaf-r` and `ngspice-46`.

Functions covered:

- `$random`, `$arandom`
- `$rdist_uniform`, `$rdist_normal`, `$rdist_exponential`, `$rdist_poisson`,
  `$rdist_chi_square`, `$rdist_t`, `$rdist_erlang`
- `$dist_uniform`, `$dist_normal`, `$dist_exponential`, `$dist_poisson`,
  `$dist_chi_square`, `$dist_t`, `$dist_erlang`

## Files

| File | Purpose |
|---|---|
| `rng_demo.va` | One module whose `V(p,n)` is a single random draw; the `dist` model parameter selects the distribution and `seed` selects the stream. |
| `verify_rng.py` | Compiles the model, instantiates N=4000 devices with seeds `1..N`, runs one `.op`, and checks each distribution's sample mean/std against the closed form, plus `$random`/`$dist_*` integrality, reproducibility and independence. |
| `rng_demo.osdi` | Compiled model (regenerated by the script). |
| `_stats.cir` | The last ngspice deck `verify_rng.py` generated (an artifact). |
| `rc_mc.va` | A first-order RC low-pass whose gain / R / C are randomized per instance via `$rdist_normal` — a Monte-Carlo device. |
| `plot_mc.py` | Runs **DC, AC and transient** on N=30 randomized `rc_mc` instances (one ngspice job) and writes `mc_dc.png`, `mc_ac.png`, `mc_tran.png`. |
| `mc_dc.png` / `mc_ac.png` / `mc_tran.png` | The three Monte-Carlo plots (see below). |
| `mc.cir`, `mc_*.txt` | ngspice deck and `wrdata` output (artifacts). |

## Run

Statistical correctness (moments of every distribution):

```
python3 verify_rng.py      # -> ALL PASS (24/24)
```

DC / AC / transient Monte-Carlo plots:

```
python3 plot_mc.py         # -> mc_dc.png, mc_ac.png, mc_tran.png
```

## DC / AC / transient Monte-Carlo (`plot_mc.py`)

`rc_mc.va` draws three independent gaussians from `$rdist_normal(seed, 0, 1)`
(same seed, three call sites → three independent streams thanks to the
per-call-site salt) to perturb its gain, resistance and capacitance about
nominal by σ = 15 %. Because each draw is stable and reproducible across an
analysis, one instance behaves self-consistently in all three sweeps:

| Plot | Analysis | What it shows |
|---|---|---|
| `mc_dc.png` | `.dc` sweep of V(in) | family of transfer lines with random slopes (random gain, mean ≈ 1.00 ± 0.17) |
| `mc_ac.png` | `.ac` 1 Hz–100 kHz | Bode-magnitude spread from randomized gain **and** cutoff (nominal fc ≈ 159 Hz) |
| `mc_tran.png` | `.tran` 1 V step | step responses with random final value and time constant (nominal τ = 1 ms) |

Each plot overlays the nominal (unperturbed) response as a dashed black line.

## How it works

Each draw is a **pure, deterministic function of `(seed, call-site)`** — there is
no persistent, in-place-advancing seed (that would change every Newton iteration
and break convergence in a SPICE engine). Consequences:

- **Reproducible**: same seed → same value, stable across the whole solve.
- **Per-instance variation**: distinct instances (distinct `seed`) draw
  independent samples — the intended use for process/mismatch modelling. This is
  why sweeping `seed` over many instances yields i.i.d. samples we can validate
  statistically.
- **Independent call sites**: a per-call-site salt decorrelates different calls
  that share a seed.

Deviation from the LRM: the seed is not advanced in place, so repeating the same
call with the same seed value repeats the value. Vary the seed to draw a
sequence. See `../Enhancement-10.md` §1 for the full rationale.

`dist` codes (see `rng_demo.va`): 0 uniform, 1 normal, 2 exponential, 3 poisson,
4 chi-square, 5 student-t, 6 erlang, 7 `$random`, 8 `$dist_uniform` (integer),
9 `$dist_normal` (integer). Parameters: `p1`/`p2` are the two real distribution
parameters, `k` is the integer shape/dof.
